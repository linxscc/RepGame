# RepGame UI 设计守则

> 适用范围：所有新建或修改的 UI 界面（局内 `Assets/Scripts/UI/Chess/`，以及局外 `Assets/Scripts/UI/Panels/`）。
> 美术风格（配色、按钮、面板质感）见 `../UIConcept/STYLE.md`，本文只管**信息怎么分层、放在哪、显示多少**。

**一句话原则：界面只回答“玩家现在要做什么决定”，其余信息一律下沉一层，由玩家主动点开。**

---

## 1. 理论依据（为什么这么做）

| 理论 | 结论 | 本项目的硬规则 |
|---|---|---|
| 渐进式披露 (Progressive Disclosure) | 先给当前决策需要的信息，细节按需再给 | 四级信息分层（第 2 节） |
| 希克定律 (Hick's Law) | 选项越多，决策越慢 | 每屏主操作 1 个，次操作 ≤ 2 个 |
| 米勒定律 / 认知负荷理论 | 工作记忆一次只能处理 4–7 块信息 | 一个面板 ≤ 5 个信息组，每组 ≤ 5 项 |
| 视觉层级 | 用大小、对比、位置区分主次 | 每屏只有 1 个视觉焦点 |
| 费茨定律 (Fitts's Law) | 目标越大、越近，越容易点到 | 高频操作放下方/右下，危险操作远离高频区 |
| 格式塔原则（邻近、相似） | 靠得近、长得像的会被视为一组 | 用留白分组，少用分割线和边框 |

---

## 2. 四级信息分层（核心规则）

| 级别 | 回答的问题 | 内容 | 触发方式 | 对应层（`ChessBattleScreen`） |
|---|---|---|---|---|
| **L0 常驻** | “现在局势怎样？” | 血量、金币、回合/计时、主按钮 | 一直可见 | `baseLayer` |
| **L1 摘要** | “有哪些？” | 列表/卡片：图标 + 名称 + ≤ 2 个关键数值 + ≤ 1 个状态标记 | 一直可见或进入功能后可见 | `baseLayer` |
| **L2 详情** | “这一个具体是什么？” | 完整属性、描述、可执行操作 | **点击** L1 元素 | `popupLayer` |
| **L3 解释** | “为什么是这个数？” | 公式、加成来源、数值拆解、规则说明 | **悬停/长按**，或点 ⓘ | `tipLayer`（`TooltipLayer.Show`） |

**规则：**

1. **一个级别只回答一个问题**，不能在 L1 里同时回答 L2、L3 的问题。
2. **信息只能往下沉，不能往上提**：拿不准放哪一级时，放更低一级。
3. **L1 卡片信息预算**：图标 + 名称 + 不超过 2 个关键数值 + 不超过 1 个状态标记。超出的一律放到 L2。
4. **数值要先问一句**：“玩家此刻要用这个数做决定吗？”不需要就下沉。
5. **L2 不叠 L2**：详情弹窗里不再打开另一个详情弹窗；更深的解释用 L3 Tooltip。弹窗最多叠一层（确认框 `ConfirmPopup` 除外）。
6. **反馈信息不占位**：瞬时提示用 `Toast`（`tipLayer`），特效和伤害数字用 `fxLayer`，不要为它们在 L0/L1 预留常驻区域。

---

## 3. 层级（渲染层）使用规范

局内 UI 统一挂在 `ChessBattleScreen.Build()` 创建的 5 个层下，**不要新建平级层，也不要把弹窗挂到 `baseLayer`**：

| 层 | 用途 | 禁止 |
|---|---|---|
| `baseLayer` | L0 + L1：HUD、棋盘、商店、羁绊栏、遗物栏 | 放详情面板、模态弹窗 |
| `dragLayer` | 拖拽中的元素 | 放常驻内容 |
| `popupLayer` | L2：详情、选择、确认、结算 | 放常驻 HUD |
| `fxLayer` | 特效、伤害数字、过场 | 放可交互控件 |
| `tipLayer` | L3：Tooltip、Toast | 放需要点击的内容 |

局外面板（登录、大厅等）同样遵循“主界面 → 二级面板 → 弹窗/提示”三层，不要把所有内容平铺在一个 Panel 下。

---

## 4. 布局与数量限制

- **视觉焦点**：每屏只有 1 个最醒目的元素（通常是主按钮或当前要操作的区域）。
- **操作数量**：主操作 1 个（朱红主按钮），次操作 ≤ 2 个（浅底细框），其余收进“…”/更多。
- **信息组**：一个面板 ≤ 5 组，每组 ≤ 5 项；超出就分页、分标签或下沉。
- **文字**：L0/L1 不出现完整句子描述；描述性文字只出现在 L2/L3。L1 名称单行，超长截断。
- **位置约定**（1920×1080）：
  - 己方信息在下方，敌方在上方（与现有 `PlayerHud` 一致）
  - 高频操作在下方/右下（拇指和鼠标的热区）
  - 投降、退出等危险操作放在角落，远离高频按钮，并经过 `ConfirmPopup` 二次确认
  - 状态类小标记（如兆象 chips）放在边角，不挡主操作区
- **留白分组**：组与组之间用间距区分，少加边框和分割线。

## 5. 做新界面前必须先输出“信息分层表”

在写任何 UI 代码或 prefab 之前，先列出这个界面要显示的全部字段，并给每个字段定级：

```
界面：<名称>
玩家在这里要做的决定：<一句话>

| 字段 | 级别 | 放置位置 | 理由 |
|---|---|---|---|
| 卡牌名称 | L1 | 卡片底部 | 识别用 |
| 攻击力 | L1 | 卡片角标 | 购买决策要用 |
| 技能描述 | L2 | 点击卡片的详情弹窗 | 不影响一眼判断 |
| 羁绊加成计算 | L3 | 详情里 ⓘ 的 Tooltip | 只有想深究的玩家才看 |
```

自检（全部为“是”才能动手）：

- [ ] L1 每个元素没有超出信息预算（≤ 2 个数值，≤ 1 个标记）
- [ ] 每个 L2 详情都有明确的入口（点哪里打开）和出口（点哪里关闭）
- [ ] 每屏只有 1 个主操作
- [ ] 没有把详情和列表放在同一层级、同一个面板里
- [ ] 每个元素都挂在了第 3 节规定的层上

---

## 6. 常见反例（禁止）

- ❌ 列表/商店卡片里直接显示完整属性表或技能描述
- ❌ 把详情面板和列表放在同一个 Panel、同一层级里平铺
- ❌ 为了“信息完整”把所有字段都塞进 HUD
- ❌ 一个界面里有多个同样醒目的主按钮
- ❌ 详情弹窗里再打开另一个详情弹窗
- ❌ 在 Tooltip 里放需要点击的按钮
- ❌ 用边框套边框来区分分组（用留白）
